# Purpose

Per `00-Project-Charter.md`'s Design Inspiration section, Kujun is named as a reference point for this product's quality bar. This document is the place to record what, specifically, this project studies and adapts from Kujun's design language — spacing, typography, hierarchy, interaction patterns, attention to detail — never to copy its screens outright.

**Status note:** this document is currently a review framework, not a completed analysis — the specific observations below must be filled in and verified by the design team through direct, current hands-on use of the app, since design details evolve between app versions and should not be asserted here from memory or assumption.

---

# What to Evaluate

When conducting the actual hands-on review, assess Kujun against each of the following dimensions and record concrete, specific observations (with screenshots if useful for the team, stored outside this Markdown file):

## Onboarding & First-Run Experience

- How many steps to a first meaningful action?
- Does it explain itself without a tutorial overlay?
- Relevant comparison point: this project's Journey 1 (`requirements/User-Journeys.md`).

## Core Loop Speed

- How many taps from opening the app to marking something complete?
- Relevant comparison point: this project's "Core Loop Is Sacred" principle (`design/UX-Principles.md`).

## Visual Hierarchy & Typography

- How many distinct type sizes/weights appear on the primary screen?
- How is whitespace used to separate sections vs. group related content?
- Relevant comparison point: `design/Typography.md`, `design/Spacing.md`.

## Color Usage

- Is color restrained (a small palette) or expressive (many saturated colors)?
- How is per-item (per-habit) color used, if at all?
- Relevant comparison point: `design/Colors.md`.

## Motion & Feedback

- What animates, and how long does it take?
- Is there a "delight" moment, and how restrained is it?
- Relevant comparison point: `design/Motion.md`.

## Consistency Correction / History Handling

- How does it let a user view or correct their past history?
- Relevant comparison point: Journey 5 (`requirements/User-Journeys.md`), `design/Components.md`'s CalendarHeatmap.

## What Feels Overbuilt or Cluttered

- Note anything that feels like feature creep or visual noise relative to this project's minimalism goals — these are explicitly *not* to be adopted.

# How Findings Feed Back Into This Project

- A finding here does not automatically become a design decision — it is raised as an input to `design/03-Design-System.md` or `design/UX-Principles.md` discussions, evaluated against the Charter's own principles first.
- Anything adopted must still be attributable to a principle already in the Charter (e.g. "this confirms our whitespace approach") rather than adopted merely because Kujun does it.
