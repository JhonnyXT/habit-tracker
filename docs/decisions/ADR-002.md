# ADR-002 — Local-Only Storage; No Backend or Accounts in V1

# Context

Habit-tracking apps commonly default to an account + backend model to enable sync and cross-device access. The Charter explicitly names "Privacy by Default" as a core philosophy and lists user accounts and backend infrastructure as Non-Goals for V1. The PRD's Technical Constraints require the app to remain fully functional offline.

---

# Decision

All V1 data (habits, completions, reminders) is stored exclusively in a local Expo SQLite database on-device (`engineering/Database.md`, `api/Data-Models.md`). There is no user account, no authentication, and no company-run backend of any kind. Data portability is provided solely through manual export/import to a user-controlled file (FR-9), never through a server.

---

# Alternatives Considered

- **Backend + account with cloud sync from day one** — rejected: directly conflicts with Charter Non-Goals and the Privacy by Default principle; also substantially increases V1 scope and attack surface (`standards/Security.md`) for a benefit (multi-device sync) not required by the core value proposition.
- **Local storage with optional anonymous cloud backup via a third-party BaaS** — rejected for V1: still introduces a network dependency and a new privacy surface not justified by the Charter's non-goals; deferred to `requirements/Roadmap.md` Horizon 2/3 as a possible future, explicitly optional addition.
- **Local storage only, with no export capability** — rejected: fails the "Privacy by Default... user data belongs to the user" principle, which requires that users not be locked into the app with no way to get their data out.

---

# Consequences

**Positive:**

- No server costs, no server security surface, no account-recovery UX to design.
- Trivially satisfies NFR-2 (Offline-First) and NFR-4 (Privacy & Data Ownership) by construction — there's no network path to accidentally violate them through.
- Simplifies `standards/Security.md`'s threat model substantially compared to a networked product.

**Negative / Trade-offs:**

- No automatic multi-device sync in V1 — a user switching phones must manually export/import (Journey 7, `requirements/User-Journeys.md`).
- Data loss on the device (without a manual export) is unrecoverable — this raises the severity of any bug affecting local data integrity (`engineering/Database.md`'s transaction/migration safety requirements, `reviews/Production-Checklist.md`'s treatment of data-loss reports as top severity).
